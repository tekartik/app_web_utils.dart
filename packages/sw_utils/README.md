# tekartik_sw_utils

Register the service worker of a Dart web app in one call, at startup:
`appInitServiceWorker()` registers `sw.js` when the browser supports
service workers, unless the page url holds `?no-sw`.

## Getting started

Not on pub.dev, add it as a git dependency:

```yaml
dependencies:
  tekartik_sw_utils:
    git:
      url: https://github.com/tekartik/app_web_utils.dart
      path: packages/sw_utils
```

Platforms: browser only, dart2js and dart2wasm (`--wasm`): it is written on
`package:web` and `dart:js_interop`.

```dart
import 'package:tekartik_sw_utils/sw_utils.dart';

Future<void> main() async {
  // Never throws: every outcome is printed to the console.
  await appInitServiceWorker();
  // ...start the app
}
```

## What it does

- Skips everything when the url holds `?no-sw` (`optionNoServiceWorker`),
  handy while developing. A worker installed before keeps controlling the
  page: unregister it in the browser devtools.
- Registers `sw.js`, relative to the page (scope: the folder of the page),
  and waits at most 500 ms: a slower registration goes on in the
  background (a `TimeoutException` is printed, not thrown).
- Service workers exist only on a secure page (https or localhost): on
  http it prints `ServiceWorkers are not supported.`
- For another script name, a scope, or to know when the worker is active,
  use `window.navigator.serviceWorker` of `package:web` (`register`,
  `ready`) yourself.

The `sw.js` itself is generated by `tekartik_sw_build`
(`packages/sw_build` of this repository).
